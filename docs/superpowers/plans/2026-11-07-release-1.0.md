# StreetQuest — propuesta de cierre y publicación
Fecha de revisión 7 de noviembre de 2026.

> Alcance 1.0 aprobado por el usuario mediante «adelante» el 7 de noviembre de 2026. Se ejecutan los bloques 1–6 y se reservan zonas y recorridos para 1.1. Los resultados de verificación y publicación se documentan en la PR y en la Release.

## Objetivo de la versión 1.0

Una persona debe poder entrar en la página principal de GitHub, entender qué hace StreetQuest, descargar el ZIP de Windows, abrir Colmenarejo sin Internet y usar sus juegos y repaso con progreso persistente. Los mapas detallados deben ayudar a orientarse sin revelar las respuestas de los juegos. La importación de otros municipios españoles debe tener un alcance probado y limitaciones explícitas.

## Estado comprobado

- React, TypeScript, Vite, Leaflet y Electron.
- Colmenarejo real incluido y apertura sin conexión.
- Adivina la calle, Localiza la calle, marcador, rachas y récord.
- Historial local por calle y modo y repaso priorizado.
- Última verificación de implementación registrada con 98 pruebas unitarias/integración y dos comprobaciones offline. No se han vuelto a ejecutar al redactar este plan.
- GitHub confirma 20 commits en feat/phase-1-map-engine por delante de main, sin commits pendientes de main.
- main conserva el README inicial.
- No se encontró un directorio .github de automatización en la inspección.
- La importación en directo desde Overpass quedó sin validar tras errores HTTP y tiempos de espera.
- El último estado comprobado de Releases estaba vacío. Se debe volver a consultar antes de publicar.
- El permiso del conector para crear PR devolvió 403 en los intentos anteriores. Publicar commits mediante Git sí funcionó.

## Enfoque propuesto

Mantener Leaflet y enriquecer el mapa 2D con edificios, usos del suelo, agua y puntos de referencia. Se conserva la capacidad de funcionar offline. Cambiar a un motor 3D añadiría otra migración y otra carga de verificación, por lo que se propone para una ampliación posterior si el usuario lo desea.

La versión 1.0 cierra el producto que ya funciona e incorpora mapas detallados. Una versión 1.1 completa zonas y recorridos. Si el usuario exige ambos modos antes del primer lanzamiento, los bloques de 1.1 pasan antes del bloque de publicación.

## Reglas comunes

- Conservar paquetes municipales existentes, progreso, rachas y récords.
- Mantener Colmenarejo usable desde la primera apertura de Windows sin acceso a la red.
- No depender de teselas remotas para representar el mapa detallado.
- Separar la etiqueta del hito de su geometría para ocultar nombres en retos.
- Guardar actualizaciones municipales de forma atómica.
- Registrar procedencia, fecha y licencia de cada fuente.
- No llamar «100 % probado» al producto basándose en el número de pruebas. La aceptación exige todos los recorridos de usuario enumerados.
- No prometer cobertura internacional mientras la búsqueda y validación estén limitadas a municipios españoles compatibles.
- No cambiar de proveedor silenciosamente. Configuración y fallos deben ser comprensibles.

## Ampliación 1.1 — cerrar zonas y recorridos

### Zonas
Definir sectores reconocibles, filtro de calles y dominio por zona. Diseñar cómo tratar calles que atraviesan varios sectores. Probar el progreso por zona sin duplicar respuestas.

### Recorridos y modo repartidor
Conservar nodos e intersecciones OSM, conectividad, puentes, túneles y sentidos de circulación. El paquete actual de líneas agrupadas y recortadas no basta para calcular rutas de forma fiable. Diseñar el grafo antes de programar el juego.

La aceptación exige que las rutas sean transitables según el modo elegido y que el juego gestione calles desconectadas. El requisito concreto de eficiencia y puntuación se diseña con ejemplos de Colmenarejo.

## Método de ejecución Superpowers

1. Revisar esta propuesta y acordar el alcance del lanzamiento.
2. Escribir un diseño por subsistema, con interfaces, compatibilidad y criterios de aceptación.
3. Usar writing-plans para cada diseño aprobado, con tareas pequeñas y archivos exactos.
4. Ejecutar de forma nativa, como se eligió anteriormente, con regresiones pertinentes y commits por tarea.
5. Verificar cada bloque y revisar el conjunto antes de publicar.

Las pruebas deterministas bloquean la entrega ante regresiones. Las pruebas contra servicios públicos se ejecutan como integración en directo, con resultados registrados. Una incidencia externa no se disfraza cambiando la prueba a una simulación.
